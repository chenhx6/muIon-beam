## 当前阶段与保留价值

项目处于科研协作系统的设计阶段。允许围绕清晰模块边界重构、收口重复策略和修复历史
技术债，不以最小 diff 为目标。不得借此覆盖其他任务未登记修改或宣称未验证功能已完成。

用户将既有验收定位为未获得认可科学成果的原型试验。保护重点是项目设计、规则、
源码、skill、测试、主意图对齐、讨论建议、失败原因及经验。旧生成模型和原始输出在
P4 按路径清单判定无用后可删除，即使它是唯一生成物；先检查它是否被当前测试或
重建链依赖。保留最少工程验收摘要、版本和删除 receipt，历史报告不改写为成功成果。
这一授权限于当前设计期原型和本次重整，不是未来正式科研数据的自动删除授权。

## 主库源码与未来托管选项

建模/模拟源码、Java 入口、C++、Python、宏、控制参数、必要的小型输入和 Manifest
优先进 `muIon-beam` 主库，允许沿用 `02_models/` 中已有源码位置，避免为上传而复制一套
源码目录。所有提交入口使用同一个路径/内容/体积判定器；构建目录、结果目录、二进制
和超限内容不因位于 source 目录而得到豁免。放宽资格不自动接管 baseline 中已有的修改。

当前 origin 仍是 Gitee；用户配置了向 `https://github.com/chenhx6/muIon-beam` 的镜像。
本次只核对 refs，不配置第二条写入通道。未来保留两个选项：用途明确的卫星库，或将
主推送迁至 GitHub；当前均不执行，不根据一个固定阈值自动新建仓库或更换 origin。

GitHub 的“强烈建议小于 5 GB”是健康建议，不是可直接硬编码的单库保证；普通 Git
单文件还有 100 MiB 限制。切换时核对当时的平台、套餐、history、LFS 和 mirror 限额。
来源：`https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github`
及 `https://docs.github.com/en/repositories/creating-and-managing-repositories/repository-limits`。

## 源码重建与 Drive 快速恢复

有源码仅代表存在重建候选。要验证可重建，还必须有完整的参数、导入几何/材料/场表等
输入、版本与数据集、编译及运行步骤、随机种子、solver/mesh 设置和合法软件模块。
从干净环境执行并通过几何、数值或统计容差检查后，才登记 `rebuild-tested`。CAD/COMSOL
二进制因元数据、网格、平台而改变哈希，不要求不合理的逐字节输出复现。

Gitee 面向接替当前用户的科研人员：允许花时间重建历史工程和继续研究。
Drive 面向当前用户设备故障后的快速恢复：项目目录镜像、已生成的重要模型/检查点、
可复用环境包和可读入口，尽量免重跑。它不是一张已验证的操作系统镜像；SolidWorks、
COMSOL 的安装、许可及主机适配仍需在恢复机器核验。运行环境由机器清单加人读说明
共同记录，不能只写 requirements.txt 就宣称商业软件与 WSL 都已恢复。

## 自动化边界

用户只描述任务，非 evolution 能力按需自动调用；本次只落实源码策略和规则/环境档案。
完整 ProjectSupervisor 自动入口、worker 生命周期和 Drive 重整继续按执行计划推进，
不得把“设计已记录”当成“宿主启动 hook 已接通”。
