# Stage1 3-D reproducibility scripts

The scripts in this directory are the reproducible implementation layer. The
compiled COMSOL Java classes and SolidWorks helper executables are retained
beside their source files because they are the exact versions used for the
saved checkpoints.

## COMSOL primary build

1. Compile `BuildStage1_3D.java` with the COMSOL 6.4 API jar.
2. Run `BuildStage1_3D.class` with `comsolbatch -np 1 -nosave` and pass the
   Stage1 root plus the supplied `muon/ne/comsol_muNe_SN.txt` stopping file.
3. Use a unique `-prefsdir`, `-configuration` and `-tmpdir` for each run so
   COMSOL batch log locks cannot mix separate checkpoints.

The builder creates the 3-D geometry, rounded annular electrodes, dielectric
liner, ground boundary, Electrostatics, Ktotal-based Geant4 stopping force,
Single_Muon_Diagnostic and Muon_Ensemble study placeholders. It saves
`comsol/stage1_3d_feasibility.mph` and exports a STEP geometry.

## SolidWorks master

Compile and run `BuildStage1SolidWorks.cs` through the SOLIDWORKS 2025 official
.NET interop assembly. It creates `cad/Stage1_Master_3D.SLDPRT`, adds the
`SIM_3D` and `REPORT_3D` configurations, writes semantic custom properties and
exports the editable master to `cad/Stage1_Master_3D.step`.

`ValidateStage1SolidWorks.cs` is read-only. `ExportStage1SolidWorksPreview.cs`
and `ExportStage1SolidWorksStep.cs` are output-only helpers.

The SolidWorks builder uses the native sketch-fillet route for the 1 mm
aperture rounding. It checkpoints and reopens after V1–V3 because SolidWorks
2025 can otherwise return a null V4 inner sketch segment after several
multi-body sketch/revolve cycles. The final validator checks both body and
face-edge topology.

## Scan and reduction order

`estimate_stage1_scales.py` → `RunStage1SingleSweep.java` →
`RunStage1Refine.java` / targeted runners → `RunStage1Ensemble.java` →
`analyze_stage1_sweeps.py` → `make_formal_figures.py` →
`build_stage1_report.py`.

All COMSOL scan CSVs remain under `intermediate/results/`; formal aggregate
tables are written under `tables/`. The stopping interface is read-only input
for this stage and is not regenerated by these scripts.

## Centered-source 100-ns workflow

`generate_centered_release.py` creates the fixed-seed 500-particle Larmor
source. Its COMSOL text file writes positions in the component geometry unit
(mm for Stage-1) and velocities in m/s; the companion CSV/JSON remains SI and
records the 9-degree (1-sigma) two-dimensional angular perturbation.

`BuildCenteredCoolingModel.java` plus `RunCenteredCoolingScan.java` perform the
no-voltage, uniform-1-T Phase-A density calibration. The first grid point
whose P90 transverse energy at 100 ns is at most 10 eV is the reported
`n_min,cool` candidate.

`BuildCenteredStage1Model.java` loads the canonical 3-D MPH, repairs the moved
stopping-table path, disables the legacy release, imports the centered release,
and exports particle histories and direct CutPlane/CutLine field data.
`run_centered_transport_scan.py` provides a serial, independently checkpointed
screening family for aperture, gap, density, and voltage changes.

Finally run `analyze_centered_results.py`, `prepare_centered_exports.py`, and
`make_centered_figures.py`; the detailed result is
`../reports/stage1_centered_source_100ns_cooling_extraction_report.md`.
